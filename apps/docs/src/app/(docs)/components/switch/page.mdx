## When to use it

Use `Switch` for a setting that takes effect immediately, with no submit step — a
notification preference, a feature flag. Use `Checkbox` instead when the choice is part
of a form that gets submitted together.

## Controlled

Under the hood it's still a checkbox — `checked` and `onChange` work exactly as they
would on a plain `<input type="checkbox">`.

## With an error

`error` works as it does on `Input`: the message renders under the row with
`role="alert"`, and the control is outlined in the danger colour. The message is a sibling
after the row, not inside a wrapper, so in a flex or grid parent it is its own item.

## Accessibility

- Renders `<input type="checkbox" role="switch">` paired with a `<label>` — `label` is
  required and is the input's only accessible name.
- `role="switch"` changes how assistive tech announces state ("on"/"off" instead of
  "checked"/"unchecked"), but the element underneath is a real checkbox, so `checked`,
  `defaultChecked`, and `onChange` all behave exactly as they do on `Checkbox`.
- **Keyboard:** `Tab` focuses, `Space` toggles — native `input` behavior.
- `role` is fixed: the type omits it from the props you can pass, so `switch` can't be
  overridden.
- Setting `error` sets `aria-invalid="true"` on the input and adds the error's id to
  `aria-describedby`, after any id you pass yourself. The message sits outside the
  `<label>`, so it never becomes part of the accessible name.
- The ref forwards to the underlying `<input>`.
