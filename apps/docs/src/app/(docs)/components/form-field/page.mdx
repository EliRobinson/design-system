## When to use it

Use `FormField` when you're labelling a control that doesn't wire its own label, hint,
and error — a plain `<input>`, a native `<select>`, a third-party widget. It owns the
`<label>` and message markup, and hands the control a bundle of accessibility props
(`aria-describedby`, `aria-invalid`, `aria-required`) through a render prop.

**Never wrap `Input` or `Textarea` in `FormField`.** Both already render their own label
and message region — nesting them produces two labels for one control. Reach for
`FormField` specifically when the control underneath doesn't do that wiring itself.

## With an error

`error` and `hint` are mutually exclusive in the rendered output — when both are set,
the error wins and the hint is hidden. `required` adds a visible `*` next to the label
(hidden from screen readers, since `aria-required` on the control already says it).

<DemoBlock file="form-field/WithError.tsx">
  <WithError />
</DemoBlock>

The error renders with `role="alert"`, the same as `Input`'s, so a message that appears
after the user has left the field — a validate-on-blur form — is announced rather than
waiting to be discovered. It is only in the page while there is an error, so it is
announced when it appears or changes, not repeated on every render.

## Something beside the label

`labelAside` renders after the label on the same row — a status badge, a small action
such as a dictation button. It sits beside the `<label>`, not inside it, so the control's
accessible name is still exactly `label`, and clicking the aside does not focus the
control. The row wraps when there is not room for both.

## Accessibility

- Renders a `<Label htmlFor={htmlFor}>` and calls `children` with a
  `{ 'aria-describedby', 'aria-invalid', 'aria-required' }` bundle — spread that bundle
  onto the control you render inside.
- `FormField` does **not** generate or set the child's `id` for you. You're responsible
  for giving the control an `id` that matches `htmlFor` — that's what makes clicking the
  label focus the field.
- `aria-describedby` is only set when `hint` or `error` is present; both share one
  generated id, since only one message renders at a time.
- The error message has `role="alert"`; the hint does not. When a hint turns into an
  error, the error is a new element rather than the hint's element with a role added, so
  screen readers announce it.
- `labelAside` is outside the `<label>`: it adds nothing to the control's accessible
  name. A button placed there needs its own accessible name and, as a primary control,
  its own 44x44 target.
- The `*` appended to a `required` label is `aria-hidden="true"` — the accessible
  requirement signal is `aria-required="true"` on the control itself, not the asterisk.
- **Keyboard:** no custom behavior of its own — once the `id`/`htmlFor` pair is wired
  correctly, clicking the label focuses the control via native browser behavior.
- The ref forwards to the outer `<div>`.
