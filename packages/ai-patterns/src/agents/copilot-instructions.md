# Copilot instructions

## UI: design system first

All UI is built from `@elirobinson/react` (components, hooks), `@elirobinson/tokens` (color, type, space, radius, shadow, motion), and `@elirobinson/ai-patterns` (UI contracts, working patterns, prompt templates). These are the primary source of components, tokens, and design patterns. See the upstream [design system](https://github.com/EliRobinson/design-system).

- Discover what exists with `pnpm ds` (also `pnpm ds props <Name>`, `pnpm ds tokens [filter]`, `pnpm ds classes`, `pnpm ds contracts`, `pnpm ds patterns`, `pnpm ds prompts`). It reads `node_modules` at run time, so it matches what is installed, which a component list from memory or from a doc may not. If it warns on stderr that `node_modules` disagrees with the lockfile, install first, because what is installed is not what CI builds. `pnpm exec elirobinson-ds` works if the `ds` script is not wired up.
- Run `pnpm ds check` after setup and after every `@elirobinson/*` upgrade. It finds the known traps that make the app look wrong with no error, and prints the fix for each.
- Import each component by its full subpath; `pnpm ds props <Name>` prints the exact import line. There is no barrel export and a bare `@elirobinson/react` import does not resolve.
- Satisfy the contracts from `pnpm ds contracts`. Each carries its own `check` and a `verifiedBy` naming the lint rule or Playwright helper that enforces it.
- Style with the component's own `variant` / `size` props; use utility classes for layout only.
- Colors, radii, shadows, durations, and font sizes come from tokens: mapped utilities (`bg-background`, `text-muted-foreground`, `border-border`, `text-accent`), `.t-*` typography classes, or `var(--token)` in arbitrary values. Do not use literal values; `@elirobinson/eslint-config` fails the build on them.
- On Tailwind v4, order the CSS entry as `@import 'tailwindcss'`, then the design system stylesheet (`@elirobinson/react/styles.css`, or `@elirobinson/tokens/tokens.css` for an app that does not import `styles.css`), then `@import '@elirobinson/tokens/tailwind.css'`. That last import is what makes the token-backed utilities resolve.
- Dark mode is `[data-theme="dark"]` (`.dark` also works). With `next-themes`, set `attribute={["data-theme", "class"]}`.
- Import `@elirobinson/react/styles.css` once, in the app shell, not per component. On Tailwind v4 that is the CSS entry above. It already imports `@elirobinson/tokens/tokens.css`; importing `tokens.css` as well bundles it twice. An app that does not import `styles.css` (no React, or per-component sheets only) imports `@elirobinson/tokens/tokens.css` itself.
- Token overrides go in an unlayered `:root` block. `tokens.css` is unlayered, so an override inside `@layer base` silently loses to it. With `next/font`, re-point the families through `--ds-font-sans-override` / `--ds-font-mono-override` instead, with the font class on `<html>`.
- Missing a piece? Compose it from primitives, then the repo's sanctioned gap-filler, then hand-roll from tokens and flag it as a design system gap worth upstreaming.
- Other component libraries (MUI, Chakra, Ant Design, Mantine, HeroUI, Headless UI, DaisyUI), direct Radix imports, and bare `@elirobinson/*` imports are blocked by ESLint.
- Functional UI copy (errors, empty states, helper and hint text, toasts, labels, button text, tooltips, confirmations, validation) is chrome: state the fact, then the consequence, then the action, and stop. Leave out unverifiable frequency claims ("almost always"), blame ("on their side", "check your connection"), filler pacing ("in a moment", "hang tight"), unprompted reassurance or apology ("don't worry", "we'll sort it out"), escalation paths nobody asked for, and enthusiasm or exclamation marks. Reassurance is fine when it answers a question the reader is actually asking, and then it is a fact: "You have not been charged." Past two short sentences, cut it back. `@elirobinson/eslint-config` reports the literal phrases at `warn` by default. Raise it once existing copy is clean with `designSystem({ copy: { severity: 'error' } })`.
- That copy rule covers chrome, not this product's editorial voice. Marketing prose, conversational surfaces, and written deliverables are content, and their voice is a deliberate design decision. Where a surface mixes the two, the chrome follows the rule and the content is left alone.
- Before calling UI work done, run `pnpm ds patterns` and work through the Definition of Done for UI work checklist it prints.
